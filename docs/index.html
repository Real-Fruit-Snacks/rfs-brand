Ethos & Editorial Voice

Core Principles & Voice

Four engineering commitments shared across all 17 active public repositories, paired with four voice tests that keep every README concise and verifiable.

01 / LOCAL

Local-first by default

Software runs on your machine against your own files, certificates, and processes—not behind a cloud service.

02 / PRIVACY

No accounts or tracking

Zero signups, zero telemetry beacons, and zero third-party analytics scripts across apps and docs.

03 / OPEN

Source-first on GitHub

Every active tool is public, inspectable, and documented plainly beside its actual inputs and outputs.

04 / DIRECT

Direct downloads & setups

Releases, source builds, and scripted setups stay straightforward and reproducible without vendor lock-in.

Plain

Short sentences and concrete nouns. Assume the reader is busy and technically capable.

Test: Could someone act on it at 2 am?

Specific

Real versions, OS names, command flags, and measured numbers instead of vague adjectives.

Test: Can every adjective become a fact?

Dry

Personality belongs in real engineering details—never hype headlines or exclamation points.

Test: Still sharp with zero emoji?

Honest

State platform constraints and caveats upfront so readers decide before installing.

Test: Is the main caveat visible early?

Banned copy: blazing powerful modern seamless supercharge awesome Welcome! coming soon — plus all emoji, shields.io rainbow badge walls, and exclamation marks in headlines.

Verified WCAG 2.1 Contrast Proof Matrix (Both Modes Simultaneously)

Every foreground token measured mathematically against all four surface tiers. Minimum targets: 4.50:1 for normal text (WCAG 1.4.3) and 3.00:1 for control borders (WCAG 1.4.11). Every cell below passes.

Color Space Rule Always interpolate Steel (h ≈ 243°) to Beacon Orange (h ≈ 44°) using Cartesian in oklab—never polar in oklch, which routes through magenta/pink at 360° and produces an off-brand violet midpoint.

Why keep vertical scrollbars below the header?
Confining scrolling to .rfs-scroll-region inside a 100dvh shell keeps navigation chrome visually uninterrupted and stops scrollbar tracks from running up into the top edge.
When should I use a toast vs. a modal dialog?
Use popover="manual" toasts for non-critical confirmations (saved, copied). Use native <dialog class="rfs-dialog is-destructive"> whenever an action deletes, clears, or overwrites user data.
Why omit headings inside <summary>?
Screen readers expose <summary> as a button and flatten nested headings, so keeping plain text directly inside <summary> preserves clean accessibility semantics.

Org Art · 3 Standards

Org Art & Where Each Asset Goes

Bespoke six-channel Cyclorama Dawn studio lighting-rig artwork (LX 001–LX 512) governed by three distinct standards: Static, Animated One-Shot, and Ambient Showcase.

STANDARD 01 [static] 0ms

Static Art Standard

Zero <style> keyframes and 100% outlined <path> glyphs. Hierarchy relies strictly on contrast, Cyclorama wash, and spatial lockup—readable in under one second and at 400px link-card scale.

Surfaces: OG cards · social headers · avatars · print · reduced-motion base

STANDARD 02 [one-shot] ≤ 1.4s

Animated One-Shot

Plays once on load (1.22s banners, ≤ 3.5s typed repo covers) using --rfs-ease and settles permanently onto the exact Static Standard frame. Pure CSS inside prefers-reduced-motion: no-preference—no JS, no SMIL.

Surfaces: Org & repo README heroes · live docs banners

STANDARD 03 [ambient] 54.4s

Ambient Showcase

Looping motion is reserved solely for multi-item proof boards that reveal changing data (3.2s dwell per row, 0 flashes/sec). Base DOM leaves item #01 legible; web embeds > 5s require a visible Pause/Play button.

Surfaces: GitHub profile cue board · interactive docs preview

# RFS Brand Rules — Cyclorama Dawn (Steel & Beacon Orange)
- Theme & Motion: Dark mode (#050507, LX 263) is the default; Light (#F5F7F9, LX 512) is opt-in toggle. Keep UI motion enabled by default.
- Palette: Glacial Steel #1F547A & Beacon Orange #F06E2B. ALWAYS Cartesian `in oklab` gradients (never polar `in oklch`). Zero neon glows or emoji.
- Typography: Self-hosted Big Shoulders Stencil (display), Albert Sans (UI/prose), Azeret Mono (code/CLI).
- Code blocks: Always show language tag + syntax coloring (.rfs-code-card) and wrap by default (.rfs-code-scroll opt-in).
- Badges & Icons: D · Terminal Token badges/chips (4px); 60-icon Precision Silkscreen set (rfs-icons.svg, 24px, 1.75px square/miter, recolorable via .rfs-icon-*).
- Chrome & Scrollbars: Zero fake macOS traffic lights; word-only cover signatures; scrollbars stay strictly below top headers (.rfs-shell + .rfs-scroll-region).
- Modals & Toasts: NEVER use native alert()/confirm()/prompt(). Prompt destructive actions with <dialog class="rfs-dialog is-destructive"> (autofocus on Cancel, .rfs-btn-fault confirm). Tint toasts by semantic status (is-ok/warn/fail/info).
- Drop-in CSS & CLI: Load rfs.css then rfs-components.css. CLI respects NO_COLOR + exit codes 0/1/2.
- README & Docs (BRAND.md §14): Keep README.md ultra-minimal (40–60 lines); move full usage, config, architecture, and dev guides into versioned docs/*.md (disable GitHub Wiki).
